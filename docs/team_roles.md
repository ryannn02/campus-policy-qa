# 校园制度问答助手团队分工

> 项目：P1 校园制度问答助手（RAG）
> 小组人数：5 人

## 角色概览

- 组长（架构与统筹）
- 成员 A：数据与解析负责人（Input 侧）
- 成员 B：检索与模型链负责人（RAG 核心）
- 成员 C：拒答逻辑与评测脚本负责人（Evaluation 侧）
- 成员 D：前端与接口负责人（输出与体验）
- 成员 E：脚本与运维支持（Glue & 文档）

## 组长（架构与统筹）

- 制定整体技术方案：数据流、RAG 分层、拒答逻辑。
- 维护 README 与 `docs/` 架构文档的一致性，决定架构演进方向。
- 拆分任务并排里程碑：基础档 / 进阶档，对齐老师文档中的指标要求。
- 负责关键接口的最终整合：
  - `config`、`contracts`、`retriever`、`chain`、`service` 串成完整调用链；
  - 保证从 CLI / Web 到 AnswerResult 的端到端流程跑通。
- 定期组织组会：每周一次进度盘点与风险复盘。

## 成员 A：数据与解析负责人（Input 侧）

- 收集校内制度文档：
  - 目标规模：≥200 份 PDF / Word / 网页；
  - 以学校官网公开文件为主，做去重与整理。
- 负责原始数据处理流水线：
  - `scripts.ingest`：`data/raw → data/parsed/*.txt → data/chunks.jsonl`；
  - 编写解析与切分脚本（含扫描件的 OCR 预案）。
- 维护文档清单与覆盖说明：
  - 标注哪些文档与哪些问题类型相关；
  - 为评测集构建提供依据，避免“评测集自己造自己答”。

## 成员 B：检索与模型链负责人（RAG 核心）

- 实现检索层 `retriever.py`：
  - 使用 bge-small-zh-v1.5 向量化；
  - 建立本地向量索引（暴力余弦 / 简单索引结构）；
  - 支持 per_doc 限额与 top-k 控制；
  - 按需扩展 BM25 + 向量多路召回与重排（进阶档）。
- 实现生成链 `chain.py`：
  - 组合 `ChatPromptTemplate → ChatOpenAI → StrOutputParser`；
  - 确保模型输出强制引用、合法 JSON 格式。
- 和组长一起调优检索与生成指标：
  - Recall@5、答案有据可依率、幻觉率；
  - 为不可回答题的拒答逻辑提供检索侧信号（分数阈值）。

## 成员 C：拒答逻辑与评测脚本负责人（Evaluation 侧）

- 根据 `architecture.md` 的拒答契约完善 `service.py`：
  - 定义 `AnswerResult`、`Citation` 结构；
  - 把 `RefuseReason` 的 code 统一成枚举或常量表。
- 构建评测集：
  - 目标规模：≥150 条问题，含可回答、不可回答、多跳整合、含歧义四类；
  - 标注每条问题对应的来源段落与可回答性。
- 编写评测脚本与报告生成：
  - 一键跑 Recall@5、答案有据可依率、拒答率、幻觉率等指标；
  - 输出 Markdown 报告 + 图表，便于期末展示与对比。
- 维护 badcase 归因表：
  - 总结各类错误对应的系统层改动（检索、提示词、拒答逻辑等）；
  - 支撑项目风险分析与改进方案说明。

## 成员 D：前端与接口负责人（输出与体验）

- 实现 Web 与 API 层：
  - `scripts.serve` 或 Web 框架入口，提供 JSON API；
  - Web 界面：问题输入框、答案展示、引用跳转原文、拒答提示。
- 覆盖关键应用场景：
  - 新生入学季高频咨询分流；
  - 辅导员 / 教务老师的随身查询。
- 性能与体验：
  - 监控 P95 响应时延，目标：基础档 ≤8s，进阶档 ≤5s；
  - 基础可用性测试（表单校验、错误提示、加载状态等）。

## 成员 E：脚本与运维支持（Glue & 文档）

- 编写 CLI 工具脚本：
  - `scripts.build_index`：从原始数据到索引的一键构建；
  - `scripts.ask`：命令行问答入口，用于调试与评测集跑批；
  - `scripts.eval_answer`：评测脚本的命令行包装，与成员 C 协同实现。
- 保证“快速开始”可复现：
  - 根据 README 中步骤验证从空环境到完整系统跑通；
  - 整理环境依赖、配置项（`.env`、模型 key 等）。
- 文档与最终展示：
  - 补充 `docs/` 下的部署说明、数据来源说明；
  - 协助准备期末展示用 PPT / 报告，将技术细节转成易懂的故事。
